# 失败分类学

> **中文** | [English](Failure-Taxonomy.md)

**这是本项目最有用的产出。**

硬件 agent 的输出通道是字符级的。目标机可以随意重新解释这些字符。这个落差产出了项目里每一个代价高昂的 bug，而修法不是更好的重试——而是教会 harness **在动手之前先对失败分类**。

## 三种失败，两种一模一样的症状

“我的文字不在屏幕上”有三种不同的成因，对应三种不同的修法。按错误的那一种去处理，只会让事情更糟，有时糟得多。

| 判据 | 成因 | 修法 |
|---|---|---|
| type 报告里的 `queued < len` | 设备根本没把它发到线上 | 传输 / HID 问题——修发送侧 |
| 动作之后屏幕**完全没变** | 按键去了别处——**焦点** | 点进目标字段，然后重打 |
| 屏幕**变了**，但文字不对 | 字符在目标机被**重新解释** | 换输入*通道*，而不是加大重试次数 |

中间和最后两行才是危险的一对，因为它们在屏幕上看起来一模一样，修法却完全相反。把它们混为一谈的模型（或开发者），会去切换输入法来修一个焦点问题，或者对着一个没有焦点的字段重打，然后这样烧掉整个任务。

**这两个判据现在都由 harness 产出，而不是由模型推断：**

- `queued=ALL N/N` 来自 HID 层，它数了自己实际发出去的东西。
- `screen since last screenshot: unchanged / changed` 来自帧指纹。
- 当一批动作什么都没改变时，动作摘要会被打上 `[NO SCREEN CHANGE]` 标记。

它们出现在每个请求顶部的状态栏里。

## 为什么“屏幕没变”是关键信号

它是唯一能把*按键从未落地*和*落地了但被转换过*区分开的判据。而这恰恰是模型靠推理到不了的情况：从模型的视角看，“我打了 `Vicrl-7391-A`，字段里是 `Vicrl--A`”和“我打了它，字段是空的”都只是*不对*，在种类上看不出任何差别。

实测的例子，说明它能抓住什么：agent 运行期间，操作者点了任务栏的语言指示器。焦点离开了记事本。agent 下一次 `type` 报告 `queued=ALL 12/12`，而编辑器里依然显示 `0 characters`。这不是输入法问题，再怎么切换也修不好——按键去了桌面。

## 通道

一旦知道字符被重新解释过，问题就变成该用*哪条通道*。设备的答案是提供不止一条，并且优先用那些根本不是字符级的通道：

| 通道 | 机制 | 在该目标机上的实测 |
|---|---|---|
| 主键盘数字行 | 默认 | ❌ 数字被输入法吃掉 |
| 小键盘 | `digits_numpad` | ❌ 同样被吃掉 |
| **绕开 GUI** | `run "cmd /c echo ... > file"`——没有编辑器，没有输入法 | ✅ |
| **剪贴板中转** | 把值放进剪贴板，再 `ctrl+v` | 尚未实测 |
| **先确认模式** | 先探针，再打字 | 正确的第一步 |

这个推广比具体某几行更重要：**当一条输出通道可以被环境改写时，就再加一条通道，以及一种能判断哪条起了作用的方法。** 重试不是第二条通道。

## 验证必须与被验证的对象分开

这是最耗时间的那个坑，而且它足够隐蔽，值得写成一条规则：

> 与被探针的动作放在同一步里发出的探针，测的是*旧*状态。

输入法切换在目标机上是异步生效的。发了三次切换，每次都紧接着在**同一批动作**里跟一个探针，三次探针全都失败——于是结论成了“这台机器上切换不起作用”。可接下来一次完全不带切换的多词输入，字母、空格和标点全都完好通过，而这只在英文模式下才会发生。**切换其实每次都生效了。** 只是探针在切换落地之前就发出去了。

假阴性比不测量更糟：它会把你送去一条根本不需要的通道。两个后果：

- 现在探针必须是**独立的一步**（一次完整的模型往返，约 4 s——远超切换稳定所需）。
- 固件在发出切换键后还会额外等 150 ms，这样同一批里的其他动作也无法跟它抢跑。

## 同一项工作里得出的另外两条规则

**不要逐字符修补文本。** 修补一个错误的字符串，会让那个把它弄坏的机制继续保持武装，下一次尝试照样坏。要修*模式*，或者清空重打。

**要知道每个清理键会毁掉什么。** 候选窗口打开时，组字还没有进入文档——所以 `escape` 丢弃它，什么也不碰。`enter` 提交它，这意味着之后必须撤销。而 `clear_first` 就是 `ctrl+a`：**整个字段**，在一个已经含有先前工作的文档上这是破坏性的。因此 harness 还提供 `replace_chars: N`——`shift+left` × N，一次精确且局部的替换，其中 N 可以从应用自己的字符数里读到。
